# Тесты и проверка

Принцип (из CommonKnowledge, `go-dev-process/test-levels.md`): утечки багов лежат там, где нет **вида** теста, а не там,
где мало покрытия. Каждый найденный баг получает метку вида и тест этого вида, который **падает без исправления**.

## Запуск

```bash
cargo test
```

```bash
python tools/mutate.py
```

`mutate.py` портит ключевые места кода (273 мутанта) и проверяет, что тесты это замечают. Мутанты проверяются
по 4 одновременно, каждый в своей копии проекта (`target/mutate/wN`), поэтому исходники проекта не трогаются и их можно
править во время прогона. Тесты на мутанте идут до первого упавшего файла тестов; прогон дольше 15 минут обрывается
и считается убитым (мутант зациклил или замедлил код). Перед мутантами копия проверяется на исходном коде — если
тесты не зелёные, прогон останавливается. Помеха антивируса (тестовый exe не запустился, «файл занят», «отказано
в доступе») убийством не считается: прогон мутанта повторяется до трёх раз.

Только часть мутантов, например после правки одного места:

```bash
python tools/mutate.py --only ИНН --only телефон
```

Выживший мутант — дыра в тестах: дописать тест, пока не будет «выжило: 0».

### Несколько файлов и связки (`tests/multi.rs`, `tests/links.rs`, `tests/hunt3.rs`)

Заказчик присылает несколько файлов; связки между колонками и файлами (организация ↔ ИНН, ФИО ↔ телефон ↔ email,
договор ↔ контрагент) должны сохраниться. Отдельного кода под каждую связку нет: каждое значение заменяется само по себе
и всегда одинаково. Поэтому тестируется главное — **одно значение узнаётся в любом виде, в любом файле, в любом режиме**.

| Тест | Вид | Что ловит |
|---|---|---|
| `links::every_link_survives_across_files_formats_and_modes` | инвариант со случайными данными | 4 человека × 11 атрибутов, 3 файла со своими наборами и порядком колонок, разные форматы, с ID и без; пакет и по очереди с ключом (разная соль). Одна сущность — один фейк везде, фейк ≠ реальному, число осталось числом, проверка молчит |
| `multi::batch_keeps_links_between_files`, `shared_key_keeps_links_between_files` | сквозной | организация в 5 написаниях, ИНН в колонке без правила, «Иванов И.И.» ↔ полное ФИО из другого файла, ИП ↔ ФИО |
| `multi::random_files_keep_entities_consistent` | инвариант | случайные наборы файлов: организации и ИНН |
| `multi::batch_preview_matches_output` | паритет | предпросмотр пакета = файлы |
| `multi::other_file_value_in_text_is_replaced_or_reported` | страж | значение из ключа в тексте: заменено, а без поиска в тексте — найдено проверкой |
| `multi::different_kinds_for_same_values_are_reported` | состояние | одни значения под правилами разных типов в разных файлах — предупреждение «…в колонках, размеченных правилами разных типов» с файлом, листом и колонкой, без самих значений; без расхождения — без предупреждения |
| `multi::unloaded_shared_key_is_kept`, `key_out_follows_found_key`, `files_in_one_folder_share_key`, `cli_batch_and_shared_key` | ключ | общий ключ папки не затирается, подхватывается окном и консолью, старый ключ переносится |
| `multi::key_has_one_row_per_value` | ключ | одно ФИО в нескольких файлах и ячейках — одна строка ключа (найдено мутацией) |
| `multi::masked_long_number_inside_text_is_replaced` | утечка | лицевой счёт под маской или «текстом» внутри примечания: поиск по цифрам знает только ИНН/СНИЛС/паспорт/счёт/телефон, такие номера ловит поиск значений в тексте (найдено мутацией) |

### Аудит безопасности 0.5.0 (`tests/exhaust5.rs`, `tests/key5.rs`, `tests/parts5.rs`)

Отдельный агент проверил 0.5.0 так же, как 0.4.0: может ли программа выдать реальные значения, испортить ключ или
исходники, повесить компьютер. Критичных находок (P0) нет. Три важные (P1) исправлены до выпуска, вместе с ними —
мелкие находки того же места. Каждый тест падал до исправления.

- **P1-1. Исчерпание номеров.** Тысячи коротких номеров (пятизначные телефоны 10000–19999 — все номера на «1»): генератор
  делал по 20 000 случайных попыток на значение (минуты), а затем отдавал реальный номер другой строки, и проверка этого
  не видела. Закрыто `x01`–`x03`, `x06`.
- **P1-2. Ключ, сохранённый в Excel.** Русский Excel при «Сохранить как CSV» превращает номера в «7,70708E+11» и срезает
  ведущие нули; такой ключ молча принимался, прежние фейки терялись, испорченные строки оставались в ключе навсегда.

### Мутационная проверка с 0.5.0

Решение владельца 2026-11-01: полный прогон всех мутантов — часы, поэтому на каждую доработку — **15–20 мутантов
на рискованный код** (запись файлов, ключ, выбор фейков, проверка), не дольше 30 минут, в фоне; выпуск прогона
не ждёт. Выживший мутант — новый тест в следующую сборку.

## Правила готовности

- Баг считается исправленным, когда есть тест, который падал до правки и проходит после (проверено откатом или мутацией).
- Логику не держать в окне: окно только рисует и вызывает библиотеку (`plan`, `preview`, `Profile::add_rules`, `detect::suggest`). Иначе её нельзя проверить тестом.
- Тесты не ослаблять. Удалять или сливать тест — только если мутация показывает, что его ловит другой.
- Сборка и тесты без предупреждений.
- Данные тестов — по форме настоящих отчётов: разделы, итоги, несколько таблиц, пропуски. Синтетика «шапка + строки подряд» таких багов не ловит.
- После крупной доработки — независимый охотник за пробелами (отдельный агент, не видит отчёт автора, находка считается только воспроизведённой на файле), затем его сценарии — в `tests/hunt.rs`, затем мутации и повторный охотник по исправлениям.
