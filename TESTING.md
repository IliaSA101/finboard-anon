# Тесты и проверка

Принцип (из CommonKnowledge, `go-dev-process/test-levels.md`): утечки багов лежат там, где нет **вида** теста, а не там,
где мало покрытия. Каждый найденный баг получает метку вида и тест этого вида, который **падает без исправления**.

## Запуск

```bash
cargo test
```

```bash
python tools/mutate.py
```

`mutate.py` портит ключевые места кода (127 мутантов) и проверяет, что тесты это замечают. Мутанты проверяются
по 4 одновременно, каждый в своей копии проекта (`target/mutate/wN`), поэтому исходники проекта не трогаются и их можно
править во время прогона. Тесты на мутанте идут до первого упавшего файла тестов; прогон дольше 5 минут обрывается
и считается убитым (мутант зациклил или замедлил код). Перед мутантами копия проверяется на исходном коде — если
тесты не зелёные, прогон останавливается.

Только часть мутантов, например после правки одного места:

```bash
python tools/mutate.py --only ИНН --only телефон
```

Выживший мутант — дыра в тестах: дописать тест, пока не будет «выжило: 0».

### Несколько файлов и связки (`tests/multi.rs`, `tests/links.rs`, `tests/hunt3.rs`)

Заказчик присылает несколько файлов; связки между колонками и файлами (организация ↔ ИНН, ФИО ↔ телефон ↔ email,
договор ↔ контрагент) должны сохраниться. Отдельного кода под каждую связку нет: каждое значение заменяется само по себе
и всегда одинаково. Поэтому тестируется главное — **одно значение узнаётся в любом виде, в любом файле, в любом режиме**.

| Тест | Вид | Что ловит |
|---|---|---|
| `links::every_link_survives_across_files_formats_and_modes` | инвариант со случайными данными | 4 человека × 11 атрибутов, 3 файла со своими наборами и порядком колонок, разные форматы, с ID и без; пакет и по очереди с ключом (разная соль). Одна сущность — один фейк везде, фейк ≠ реальному, число осталось числом, проверка молчит |
| `multi::batch_keeps_links_between_files`, `shared_key_keeps_links_between_files` | сквозной | организация в 5 написаниях, ИНН в колонке без правила, «Иванов И.И.» ↔ полное ФИО из другого файла, ИП ↔ ФИО |
| `multi::random_files_keep_entities_consistent` | инвариант | случайные наборы файлов: организации и ИНН |
| `multi::batch_preview_matches_output` | паритет | предпросмотр пакета = файлы |
| `multi::other_file_value_in_text_is_replaced_or_reported` | страж | значение из ключа в тексте: заменено, а без поиска в тексте — найдено проверкой |
| `multi::different_kinds_for_same_values_are_reported` | состояние | одни значения под разными типами — предупреждение без самих значений |
| `multi::unloaded_shared_key_is_kept`, `key_out_follows_found_key`, `files_in_one_folder_share_key`, `cli_batch_and_shared_key` | ключ | общий ключ папки не затирается, подхватывается окном и консолью, старый ключ переносится |
| `multi::key_has_one_row_per_value` | ключ | одно ФИО в нескольких файлах и ячейках — одна строка ключа (найдено мутацией) |
| `multi::masked_long_number_inside_text_is_replaced` | утечка | лицевой счёт под маской или «текстом» внутри примечания: поиск по цифрам знает только ИНН/СНИЛС/паспорт/счёт/телефон, такие номера ловит поиск значений в тексте (найдено мутацией) |

## Правила готовности

- Баг считается исправленным, когда есть тест, который падал до правки и проходит после (проверено откатом или мутацией).
- Логику не держать в окне: окно только рисует и вызывает библиотеку (`plan`, `preview`, `Profile::add_rules`, `detect::suggest`). Иначе её нельзя проверить тестом.
- Тесты не ослаблять. Удалять или сливать тест — только если мутация показывает, что его ловит другой.
- Сборка и тесты без предупреждений.
- Данные тестов — по форме настоящих отчётов: разделы, итоги, несколько таблиц, пропуски. Синтетика «шапка + строки подряд» таких багов не ловит.
- После крупной доработки — независимый охотник за пробелами (отдельный агент, не видит отчёт автора, находка считается только воспроизведённой на файле), затем его сценарии — в `tests/hunt.rs`, затем мутации и повторный охотник по исправлениям.

## Ручная проверка окна (перед передачей сборки)

Открыть `samples/demo_dashboard.xlsx` и свой реальный отчёт:

1. «Автоподбор: все листы» → подсветка ровно на данных, без заголовков, «Итого», ставок.
2. Протянуть мышью по части подсвеченного диапазона → «Добавить правило» → правило сузилось (в статусе «заменено»).
3. Shift+щелчок для длинного диапазона; щелчок по букве колонки — вся колонка; «Взять выделение» у правила.
4. Прокрутить вправо и вниз → номера строк и буквы колонок на месте; подсказка у ячейки показывает адрес.
5. «Обезличить и сохранить…» → в журнале «реальных значений… не найдено», результат открывается в Excel без «восстановления».
6. Закрыть и открыть тот же файл → в статусе «профиль… загружен; ключ… подключён», предпросмотр показывает те же фейки, что в файле.
7. Окно узкое (около 1000 px) — панели не налезают друг на друга.
8. «Открыть Excel…» с двумя файлами (Ctrl+щелчок) → слева список «Файлы (2)», у каждого свои правила; переключение
   между файлами сохраняет правила и лист; «убрать» убирает файл из набора; снятая галочка — файл перечёркнут,
   кнопка «Обезличить отмеченные файлы (1 из 2)…».
9. «Обезличить все файлы (2)…» → выбрать папку → оба результата там, в журнале по отчёту на файл; общий ключ в папке
   первого файла. Один контрагент в обоих файлах — один фейк.
10. Закрыть, открыть второй файл отдельно → ключ подключён, предпросмотр показывает те же фейки.
11. Десять файлов → границу между «Файлами» и «Листами» можно тянуть мышью, оба списка прокручиваются.
12. Выделить колонку налогов вместе с шапкой «Налог» → тип «Шаблон» → «Добавить правило» → в статусе «„Налог“ — заголовок…»,
    у правила подпись «Налог», строки со следующей; «Взять выделение» на другой колонке — подпись из её заголовка.
13. «Вне разметки» → «не трогать» → предпросмотр и результат: ячейки без правил как в исходнике.
14. Колонка «Дата» показывает даты как в Excel (01.01.2019), а не числа.
15. Щелчок по ячейке → стрелки двигают зелёную рамку, таблица прокручивается за ней; Ctrl+→ — к последней колонке
    с данными, Shift+↓ — выделение растёт; в поле «Диапазон» стрелки двигают курсор текста, а не таблицу.
16. Двойной щелчок по заголовку колонки → выделено под шапкой до конца, «до конца листа» отмечено; «Добавить
    правило» → правило «…:C…». Правило B2:B11 при данных до строки 20 → красное предупреждение под правилом.
17. Файл на 500 000 строк: открывается за секунды; при правке правила крутится значок, окно не замирает.
18. Заголовок окна и свойства exe («Подробно») — с версией; архив, папка в нём и exe — с версией в имени.
19. Буквы колонок и номера строк — на цветной полосе, крупно; у активной ячейки подсвечены её буква и номер, в углу — адрес.
20. Щелчок по ячейке под правилом → правило справа в оранжевой рамке и прокручено в вид; стрелками из правила — рамка снимается.
21. «Добавить папку…» → папка с подпапками → в списке все .xlsx, кроме `…_anon`; снять галочку → файл перечёркнут,
    в результатах его нет.
