# finboard-anon — обезличивание Excel-дашбордов

Заменяет реальные персональные данные в `.xlsx` на правдоподобные фейки с ID,
сохраняя дашборд рабочим: формулы, сводные таблицы, диаграммы и оформление остаются как были.

```
Иванов Иван Иванович      →  Калашников Анатолий Алексеевич (ID 1)
Сидоров П.А.              →  Потапов С.В. (ID 2)          ← тот же человек, что и
Сидоров Пётр Алексеевич   →  Потапов Святослав Владимирович (ID 2)
+7 (916) 123-45-67        →  +7 (900) 000-00-01           ← ID в последних цифрах
79161234567 (число)       →  79000000001                  ← тот же номер — тот же ID
client1@mail.ru           →  aleksey.lebedev.1@example.com
7707083893 (ИНН, число)   →  9900000018 (число)           ← контрольная цифра верная, инспекции «00» не бывает
ООО «Ромашка» / Ромашка   →  ООО «Вектор» (ID 3) / Вектор (ID 3)   ← одна организация в любом написании
```

Несколько файлов одного заказчика обрабатываются с **общими фейками**: один человек, одна организация,
один ИНН, телефон, email, дата — один фейк во всех файлах. Поэтому любые связки между колонками и файлами
(организация ↔ ИНН, ФИО ↔ телефон ↔ email ↔ СНИЛС, договор ↔ контрагент, код клиента ↔ ИНН) сохраняются:
каждое значение заменяется само по себе и всегда одинаково, и пары остаются парами.

**Для кого:** для тех, кому нужно передать Excel-дашборд с персональными данными клиентов
(разработчику, аналитику, подрядчику) так, чтобы он остался рабочим, а реальных данных в нём не было.
Программа работает на компьютере пользователя без интернета и ничего никуда не отправляет.

**Статус:** ранняя версия для тестирования на реальных файлах. Перед передачей результата
просмотрите отчёт проверки — он показывает, что могло остаться незаменённым.

## Скачать

Готовая сборка под Windows 10/11 (64 бит), установка не нужна:
**[последний выпуск](https://github.com/IliaSA101/finboard-anon/releases/latest)** — архив
`finboard-anon-<версия>-windows-x64.zip` (все версии — на странице [Releases](https://github.com/IliaSA101/finboard-anon/releases)).

Распакуйте архив и запустите `finboard-anon-<версия>.exe`; внутри — `ИНСТРУКЦИЯ.txt` и пример с вымышленными данными.
Версия видна в имени архива, папки и exe, в заголовке окна и в свойствах exe («Подробно»).
Программа не подписана: если Windows покажет «Система Windows защитила ваш компьютер» —
«Подробнее» → «Выполнить в любом случае».

**Антивирус.** Касперский может показать для exe программы «Кто-то пытается использовать ресурсы вашего компьютера
для майнинга криптовалюты» или «VHO:Trojan-Spy.Win32.Convagent.gen». Это ложное срабатывание проверки поведения:
программа новая, без цифровой подписи и на большом файле загружает процессор на 100 %. Сетевого кода в ней нет,
других программ она не запускает, исходный код открыт здесь. Что делать: в уведомлении выбрать «Игнорировать»
(или «Добавить в исключения» — только для этого exe). Не нажимайте «Устранить» во время обработки — это остановит
программу; исходники и ключ при этом не меняются, рядом с результатами могут остаться временные `…_anon.xlsx.tmp` —
их можно удалить. Что exe тот самый, проверяется по `SHA256SUMS.txt` со страницы выпуска:
`Get-FileHash finboard-anon-<версия>.exe` в PowerShell должен дать ту же строку.

## Сборка из исходников

Нужен [Rust](https://rustup.rs/) (проверено на тулчейне `stable-x86_64-pc-windows-gnu`):

```bash
cargo build --release
```

```bash
cargo test
```

Готовые программы — в `target\release\`. Архив для выпуска собирает `tools\release.ps1`
(ресурсы exe с версией, сборка без путей машины, архив с версией в имени, контрольные суммы).

## Запуск

- **Окно:** `target\release\finboard-anon.exe` (можно перетащить в окно один или несколько .xlsx, или
  `finboard-anon.exe файл1.xlsx файл2.xlsx профиль.json`).
- **Консоль (повторная обработка по готовым профилям):**

```bash
finboard-anon-cli --profile профиль.json --in данные.xlsx --out данные_anon.xlsx
```

```bash
finboard-anon-cli --profile договоры.json --in договоры.xlsx --out договоры_anon.xlsx --profile платежи.json --in платежи.xlsx --out платежи_anon.xlsx
```

  Второй вариант — пакет: несколько файлов за один вызов, у каждого свой профиль, фейки и ключ общие.
  Ключ по умолчанию — общий ключ папки первого файла; если он уже есть, он подхватывается и дополняется
  (`--load-key` / `--key` — указать другой). `--no-key` — без ключа совсем: найденный ключ не читается
  и не меняется, новый не пишется (фейки и ID — заново); вместе с `--key` или `--load-key` — ошибка.

Тесты и ручная проверка окна — в [TESTING.md](TESTING.md): `cargo test` и мутационная проверка `python tools/mutate.py`.

## Как пользоваться окном

1. **Открыть Excel…** (можно выбрать сразу несколько файлов), **Добавить файл…** или **Добавить папку…**
   (все .xlsx/.xlsm из папки и подпапок; папку можно и перетащить в окно) — слева список файлов
   и листы текущего файла, в центре содержимое листа. У каждого файла свои правила. Галочка у файла — обрабатывать
   его или нет («все» — отметить или снять все), «убрать» — убрать файл из списка.
   Из папки не берутся результаты прошлых запусков: `X_anon.xlsx` пропускается, только если рядом с ним лежит
   его исходник `X.xlsx`. Файл, обезличенный заранее другим способом (исходника рядом нет), — берётся.
   Ярлыки-ссылки на папки и точки соединения (junction) внутри папки не открываются — чужие файлы не подмешиваются,
   обход не зацикливается. Файлы открываются в фоне: окно не замирает, в строке состояния — «Открытие файлов: 3 из 120 — Продажи.xlsx».
2. **Автоподбор** ищет заголовки «ФИО», «Исполнитель», «Телефон», «ИНН» и т.п. в строке заголовков таблицы
   и берёт строки под ними до пустой строки, строки «Итого» или следующего заголовка
   (на листе может быть несколько таблиц). Названия разделов вроде «Итоги по исполнителям» не считаются заголовками.
3. Поправить/добавить правило (лист + колонка + диапазон строк + тип):
   - протянуть мышью по ячейкам, или щелчок — начало, **Shift+щелчок** — конец;
   - колонка целиком: щелчок по букве или **двойной щелчок** по заголовку — всё под шапкой до конца листа,
     двойной щелчок по ячейке — от неё до конца; выделение до последней строки даёт правило «до конца»;
   - клавиатура как в Excel: стрелки, Shift+стрелка вверх/вниз, Ctrl+стрелка (к краю данных), PageUp/PageDown,
     Home, Ctrl+Home/End (пока курсор в поле ввода — стрелки остаются полю);
   - или ввести диапазон: `C5:C120`, `C5:C` (до конца листа), `B5:D100` (несколько колонок);
   - **Добавить правило**: пересекающееся правило той же колонки заменяется новым (так диапазон сужают);
   - или **Взять выделение** у правила справа.
   Номера строк и буквы колонок закреплены и выделены цветом, колонка и строка активной ячейки подсвечены,
   в левом верхнем углу — её адрес. Активная ячейка под правилом — это правило справа обведено и прокручено
   в вид: его можно сразу поправить.
4. Справа у каждого правила — название колонки из шапки таблицы («Покупатель»), **Тип правила:**, число ячеек
   и предпросмотр «реальное → фейк» (считается в фоне). Предпросмотр считается по первым 20 000 строк каждого листа —
   тем, что видны в окне; на листе длиннее подпись «≈ N ячеек в первых 20000 строках». Точное число замен и проверка —
   в отчёте после обработки (правило «до конца» обрабатывает весь лист). Если ниже конца правила в колонке ещё есть
   данные — предупреждение (и в отчёте). Там же поле **Связь:** — пустое («общая») или слово, которое отделяет
   колонку от остальных (см. [Связь](#прослеживаемость)).
5. **Обезличить и сохранить…** (один файл) или **Обезличить все/отмеченные файлы…** (несколько — спросит папку для
   результатов) — результаты `<имя>_anon.xlsx`; рядом с исходниками — профили `<имя>_профиль.json`, в папке
   первого файла — общий ключ `КЛЮЧ_ОБЕЗЛИЧИВАНИЯ_НЕ_ПЕРЕДАВАТЬ.csv`.
   При следующем открытии файлов из этой папки профиль и ключ подхватываются автоматически — даже если
   обрабатывать файлы по одному в разные дни, фейки будут те же.
   Во время обработки внизу — полоса хода: процент, какой файл (если их несколько — «Файл 2 из 10: Продажи.xlsx»),
   этап (сбор значений, запись, проверка результата) и сколько примерно осталось (`37 % — Файл 2 из 10: Продажи.xlsx — запись · осталось ≈ 1 мин 20 с`;
   первые секунды — «оценка…»). По окончании в строке состояния — сколько заняло: «Готово: … — за 2 мин 05 с».
   Закрыть окно во время обработки — вопрос «Идёт обезличивание. Прервать?»: «Прервать и закрыть» удаляет
   записанное этим запуском, прежние результаты и ключ остаются как были. Как записываются результаты и ключ —
   [ниже](#запись-результатов-и-ключа).
6. Внизу — отчёт по каждому файлу. По каждому правилу строка
   `Продажи!B2:B… — колонка «Покупатель», правило «Организация»: заменено ячеек 1250`
   (название колонки — из шапки; у таблицы без шапки его нет; у правила со связью — `…, связь «контрагент»: …`).
   В журнале строка «Новых значений (нет в ключе): N» — сколько значений прибавилось к ключу (с ключом
   и тем же файлом — 0). Последняя строка — итог проверки результата
   («Проверка обезличенного файла: …», см. [ниже](#что-именно-меняется-в-файле)).

Заголовки («Исполнитель», «ФИО»…) и «Итого» не заменяются, даже если попали в диапазон.
Приписка «(ID n)» от прошлого обезличивания отбрасывается, пометки в скобках вроде «(стажёр)» сохраняются.

Проверить автоподбор без окна: `finboard-anon-cli --detect файл.xlsx`.

## Типы замены

| Тип | Пример результата | ID |
|---|---|---|
| ФИО | `Петров Олег Сергеевич (ID 12)`; пол, порядок слов, инициалы и регистр сохраняются | да |
| Фамилия / Имя / Отчество | те же фейки, что и в полных ФИО (Иванова → Петрова) | по желанию |
| Email | `oleg.petrov.12@example.com` (несколько адресов в ячейке — каждый отдельно) | в адресе |
| Телефон | `+7 (900) 000-00-12`, формат исходника | в номере |
| ИНН / СНИЛС | ID внутри, контрольные цифры корректны | в номере |
| Паспорт | `99 00 000012` | в номере |
| Адрес | `г. Казань, ул. Садовая, д. 5, кв. 7 (ID 12)` | да |
| Организация | `ООО «Вектор» (ID 12)`; форма и кавычки как в исходнике; ИП — с тем же фейковым ФИО, что и в колонке ФИО. Снаружи кавычек остаётся только форма (ООО, АО, «Общество с ограниченной ответственностью»…): `(М) ООО «Восход» (Москва)` → `ООО «Вектор» (ID 12)` — пометки, города, «Филиал №5» в фейк не переносятся | да |
| Номер (счёт/карта/договор) | цифры → ID, формат сохраняется; число остаётся числом. Короткий код (до 4 цифр): `Дог1` → `Дог900017` — никогда не совпадает с настоящим | в номере |
| Дата рождения | сдвиг ±180 дней, одинаковый для одной даты в любом виде (число Excel, «15.07.1980», «1980-07-15») | — |
| Маска | каждая буква и цифра → случайная того же вида и регистра, знаки как есть: `АБ-123` → `КМ-570` | — |
| Шаблон: подпись + номер | `Налог 1`, `Должность 2`; подпись берётся из заголовка колонки, у каждой подписи своя нумерация | да |
| Очистить | пусто | — |
| Не менять (защитить) | ячейки остаются как есть, даже если те же значения заменяются в других местах | — |

**Шаблон.** Подпись подставляется из заголовка над диапазоном («Налог» → `НДФЛ` = `Налог 1`, `НДС` = `Налог 2`).
Если шапка попала в выделение, она не заменяется и становится подписью. Подпись можно поправить в правиле.

**Вне разметки** (настройка внизу окна) — что делать с теми же значениями в ячейках без правил:
«заменять везде» (по умолчанию: целые ячейки, внутри текста и формул), «только целые ячейки» или «не трогать»
(формулы без правил тоже не меняются — `СЧЁТЕСЛИ` по реальному ФИО после пересчёта даст 0).
Отдельные области можно защитить правилом «Не менять (защитить)». Сводные, диаграммы и примечания меняются всегда —
иначе в них останутся реальные данные. Оставленное по настройке проверка тоже покажет — отчёт об этом предупредит.

## Прослеживаемость

- Одинаковое значение везде получает **один фейк и один ID** — на всех листах, в сводных, диаграммах, формулах.
- Одно значение узнаётся в любом написании, и фейк у него один:
  - телефон — по номеру: `+7 (916) 123-45-67`, `8 916 123 45 67`, число `79161234567`;
  - ИНН, СНИЛС, паспорт, счёт — по цифрам: `7707083893` числом, `77 07 083893`, `ИНН: 7707083893`;
    один номер под типами «ИНН», «СНИЛС», «Паспорт», «Номер» получает одни и те же фейковые цифры;
  - организация — по названию и форме, без учёта кавычек и записи формы: `ООО «Ромашка»`, `ООО "Ромашка"`,
    `Ромашка, ООО`, `Общество с ограниченной ответственностью «Ромашка»` — одна организация; внутри текста
    («Оплата ООО «Ромашка»») — тоже, и всегда с тем же ID, что в колонке: `Оплата ООО «Вектор» (ID 12)`
    (ID — после закрывающей кавычки). `АО «Ромашка»` — другое юрлицо: свой фейк и свой ID. Название без формы
    (`Ромашка`) — та же организация, если в данных у этого названия одна форма, и отдельная, если форм несколько
    (чтобы не приписать данные чужому юрлицу);
  - email и адрес — без учёта регистра и лишних пробелов; дата — по дню.
- «Иванов И.И.» связывается с «Иванов Иван Иванович», если такой человек в данных один, — в том числе в другом файле.
- Значение, размеченное правилом в одном файле, заменяется и в других файлах — даже в колонке без правила
  (ИНН контрагента в выгрузке платежей).
- Связка «организация — ИНН — КПП» сохраняется во всех файлах сама: каждое значение всегда заменяется одинаково
  (между запусками — по ключу), поэтому одна организация везде получает один фейк, её ИНН — один фейковый ИНН,
  КПП (правило «Номер») — один фейковый КПП.
- Если одно и то же значение размечено правилами **разных типов** — в одном файле или в разных (в одной колонке
  «ФИО», в другой «Организация»; в одном файле «ИНН», в другом «Шаблон»), фейки у него разные. Тогда в отчёте
  предупреждение (без самих значений):
  «Внимание: 1 одинаковое значение есть в колонках, размеченных правилами разных типов: колонка «Ответственный»
  (Продажи.xlsx, лист Л, A) — правило «ФИО»; колонка «Покупатель» (Продажи.xlsx, лист Л, B) — правило «Организация».
  Они получат разные фейки. Если это одни и те же люди или организации и связь нужна — поставьте колонкам один тип
  правила; если совпадение случайное — ничего делать не нужно». Значение могло прийти и из ключа прошлых запусков —
  тогда в списке «ключ прошлых запусков — правило «…»». Два правила «Шаблон» с разными подписями и колонки
  с разной «Связью» — намеренное разделение, о них не предупреждается: предупреждение о разных типах — только
  внутри одной связи.
- **Связь — как развести похожие, но несвязанные колонки.** Одно значение под одним типом везде получает один фейк —
  например, «Москва» в колонках «Город организации» и «Город контрагента». Если колонки не связаны, впишите у правила
  в поле **«Связь:»** слово, например «контрагент»: у колонок с этим словом свои фейки, и «Москва» в «Городе
  организации» и в «Городе контрагента» станет разными городами.
  - Пустое поле («общая») — как раньше: одно значение одного типа везде получает один фейк.
  - Одно слово связывает колонки между собой на любых листах и в любых файлах пакета. Регистр и лишние пробелы
    не важны («Контрагент» и «контрагент » — одна связь); уже вписанные слова можно выбрать из списка рядом с полем —
    так не будет опечаток. У «Очистить» и «Не менять» поля нет — фейков у них нет.
  - ID общие для всех связей: разные значения не получат один фейк и в разных связях, а одно значение в двух
    связях получает два фейка с разными ID.
  - В ключе тип со связью пишется через «@»: `ФИО+ID@контрагент`. Профили и ключи прежних версий читаются без
    изменений (у них все колонки — в общей связи); у колонки со связью по старому ключу будут новые фейки.
  - Вне разметки (другие колонки, текст, формулы, сводные, примечания) у значения, размеченного в нескольких
    связях, ставится фейк общей связи, а если в общей его нет — связи первого по порядку правила. Об этом в отчёте
    одна строка (без самих значений): «1 значение размечено в колонках с разной «Связью» и получило в них разные
    фейки. …».
  - Прежний обход — «Шаблон» с разными подписями — больше не нужен (и по-прежнему работает).
- **Разные значения — разные фейки.** Разные номера (ИНН, СНИЛС, паспорт, счёт, КПП, ОГРН, карта, телефон, короткие
  коды) получают разные фейковые номера — и с ID, и без; фейк никогда не совпадает с настоящим номером из данных или
  ключа. Большой ID не повторяет маленький: ID 100001 занимает соседние разряды номера и не даёт тот же ИНН, что ID 1.
  Адреса без ID и названия организаций тоже не совпадают. В 0.4.0 при сотнях ИНН без ID два разных контрагента могли
  получить один фейк. Ключ 0.4.0 воспроизводит прежние фейки ячейка в ячейку — в том числе такие совпадения: в уже
  переданных файлах они остаются, новые значения получают свои.
- **Ключ** (`КЛЮЧ_ОБЕЗЛИЧИВАНИЯ_НЕ_ПЕРЕДАВАТЬ.csv`: Тип; ID; Реальное значение; Фейковое значение) — один на папку.
  Открывается в Excel и позволяет по ID найти реального человека. Ключ содержит персональные данные — храните у себя.
  С ключом те же люди и организации получают те же ID и фейки в любом файле и при любом запуске.
  Ключ прежних версий (`<имя>_КЛЮЧ_НЕ_ПЕРЕДАВАТЬ.csv`) тоже подхватывается, а новые записи идут в общий.
- Прогон без ключа («Не использовать») не затирает общий ключ: прежний сохраняется как `…_прежний.csv`.
- Перед перезаписью ключа рядом сохраняется его копия `КЛЮЧ_ОБЕЗЛИЧИВАНИЯ_НЕ_ПЕРЕДАВАТЬ_копия.csv` (одна,
  обновляется каждым запуском). В ней тоже настоящие данные — не передавайте её.
- Ключ, пересохранённый в Excel с английскими настройками, LibreOffice или Google Таблицах (разделитель «,» или
  табуляция), читается. Если ключ повреждён (нет заголовка, не UTF-8, строка с неполными полями), программа
  останавливается с ошибкой «Ключ НЕ изменён» и ничего не записывает. Верните ключ из `…_копия.csv` или сохраните
  его как CSV UTF-8 с разделителем «;».
- Пакет (все файлы за один прогон) надёжнее, чем по очереди: фейк заранее не совпадёт ни с одним реальным
  значением ни одного файла пакета, а сокращения «Иванов И.И.» связываются с полными ФИО из всех файлов.
  По очереди фейк учитывает только уже обработанные файлы.

## Можно ли восстановить реальные данные

По одному обезличенному файлу — нет: фейк выбирается по хэшу «соль + значение», ID — порядковый номер.
Соль случайная на каждый запуск и нигде не сохраняется, поэтому подобрать фейки для подозреваемых людей
нельзя, а профиль (`.json`, только правила и настройки) можно пересылать.
Обратно — только по ключу; он же сохраняет те же фейки и ID между запусками. Оговорки:

- Намеренно сохраняются пол, формат («Фамилия И.О.»), код страны телефона, первые 4 цифры номеров
  от 12 цифр, примерный год рождения (сдвиг ±180 дней).
- Колонки без правил (суммы, города, даты сделок) не меняются — по их сочетанию клиента иногда можно узнать.
  Это псевдонимизация: для передачи разработчикам обычно достаточно, для публикации — нет.

## Что именно меняется в файле

Программа правит XML внутри xlsx, не пересохраняя книгу через Excel:

- ячейки в диапазонах правил (формулы не трогаются — они пересчитаются от фейков);
- общие строки, кэши результатов формул, строки внутри формул (`СУММЕСЛИ(…;"Иванов И.И.";…)`);
- кэш сводных таблиц (по строкам и колонкам источника), кэши диаграмм, примечания, надписи;
- ФИО/email/телефоны/организации внутри длинного текста («Ответственный: Иванов Иван Иванович»,
  «Оплата ООО "Ромашка"») — по границам слов;
- длинные числа (ИНН, телефон, счёт) в колонках без правил, если такое же значение обработано здесь, в другом
  файле пакета или есть в ключе;
- автор и компания в свойствах файла, авторы примечаний;
- служебные поля, где Excel хранит пользователя: имя в защите от записи и в журнале общей книги, кто обновлял
  сводную, папка, где сохранялась книга; имя пользователя в путях `C:\Users\<имя>\…` (гиперссылки, внешние книги,
  подключения, база гиперссылок) заменяется на `user`. Пути в тексте ячеек меняют только правила;
- `fullCalcOnLoad` — Excel пересчитает формулы при открытии.

- формулы под правилами (например, ФИО из другой книги): формула остаётся, кэш результата заменяется фейком,
  кэш внешней ссылки — тоже;
- формулы, результат которых зависит от ячеек с ПДн (`ЛЕВСИМВ(ФИО)`, `ТЕКСТ(дата)`, `=C2`): если результат
  совпадает с обработанным значением — заменяется, иначе кэш **очищается**. Excel пересчитает при открытии;
  программы, читающие файл без пересчёта (pandas, openpyxl), увидят в таких ячейках пусто. Числовые итоги
  (СУММЕСЛИ, СЧЁТЕСЛИ) не очищаются;
- даты в книгах «1904», текст, разрезанный на фрагменты форматирования, шапки умных таблиц и ссылки на их
  колонки, адреса в гиперссылках `mailto:`.

Миниатюра первого листа (`docProps/thumbnail`, Excel сохраняет её при включённом «Сохранять эскизы») в результат
не попадает. В настройках принтера стираются имя принтера, сервера печати и данные драйвера; бумага и ориентация
остаются.

Модель данных Power Pivot, запросы Power Query, внедрённые объекты (другие книги, документы), макросы и рисунки
сохраняются как есть — программа их **не обезличивает и не проверяет**, а в них могут быть реальные данные. Если
они есть, в отчёте появляется строка «Внимание: в книге есть …» с советом, что сделать перед пересылкой (удалить
таблицы модели, запросы, внедрённые объекты, сохранить без макросов, просмотреть рисунки).

Всё остальное копируется байт-в-байт.

После записи результат **проверяется**: программа заново читает обезличенный файл (все листы, общие строки,
формулы, сводные, диаграммы, примечания, служебные части) и ищет в нём реальные значения:

- все значения размеченных колонок этого файла;
- значения из других файлов пакета и из ключа прошлых запусков (те, что ищутся и внутри текста);
- названия всех организаций прогона;
- номера (ИНН, СНИЛС, паспорт, счёт, телефон) — по цифрам, в любой записи («77 07 083893», число).

Текст ищется как есть, ЗАГЛАВНЫМИ и строчными; значения короче 4 знаков (и числа короче 9 цифр) не ищутся —
слишком легко совпасть случайно.

Итог — последняя строка отчёта: «Проверка обезличенного файла: реальных значений из размеченных колонок в нём
не найдено.» или «Проверка обезличенного файла: в нём ещё встречаются реальные значения:» и ниже — где именно
(часть файла, сколько раз, примеры). Примеры — только намёком: «И*** И***», «*** 93»; самих значений в журнале нет,
его можно пересылать. Обычно это ячейки вне правил — добавьте правило и повторите.
Если в книге есть части из абзаца выше, итог честно говорит: «…в листах и XML-частях реальных значений из
размеченных колонок не найдено; двоичные части (см. «Внимание» выше) не проверялись.»
Значения колонок без правил (суммы, города) проверка не ищет — она их не знает.

## Запись результатов и ключа

- Пока идёт обработка, рядом с ключом лежит замок `КЛЮЧ_ОБЕЗЛИЧИВАНИЯ_НЕ_ПЕРЕДАВАТЬ.csv.lock`. Второй запуск на том же
  ключе (другое окно, командная строка) получает «Ключ сейчас занят другим запуском обезличивания…» и ничего не пишет:
  иначе два запуска выдали бы новым людям одинаковые ID. Брошенный замок (программа закрылась аварийно или замку
  больше 12 часов) убирается сам.
- Ключ изменился, пока шла обработка (запуск прежней версии, правка вручную) — ошибка «Ключ … изменился, пока шла
  обработка…», ничего не записано: запись затёрла бы чужие строки. Запустите снова — ключ загрузится заново.
- Результаты сначала пишутся во временные файлы рядом (`…_anon.xlsx.tmp`), каждый проверяется, и только потом всё
  встаёт на место вместе: сначала ключ, затем результаты. Если какой-то результат или ключ открыт в Excel — ошибка
  «Не заменяется «…»: файл открыт в другой программе (закройте файл в Excel)…» с именем файла; прежние результаты
  и ключ не тронуты, временных файлов не остаётся. Записанное сразу сбрасывается на диск, а не остаётся в памяти Windows.
- Одинаковые имена из разных папок в одной папке результатов: `отчет_anon.xlsx`, `отчет_anon_2.xlsx`. Номер зависит
  от полных путей исходных, а не от порядка открытия — повторный прогон перезаписывает результат того же исходного.
- Результат не может совпадать с исходным, в том числе через другое имя того же файла (жёсткую ссылку):
  «…файл результата совпадает с исходным — выберите другое имя».

## Ограничения

- Только `.xlsx` / `.xlsm` (`.xls` пересохраните в Excel). Файл не должен быть защищён паролем.
- Большие листы читаются и пишутся потоком: 500 000 строк × 100 колонок (400 МБ) — около 2 минут, меньше 100 МБ
  памяти. В окне показываются первые 20 000 строк листа, предпросмотр у правил считается по ним же; обработка
  и проверка идут по всему листу.
- Значения, которые не попали в правила и не совпадают с обработанными, не меняются — смотрите отчёт проверки.
- Сводная с группировкой дат (по месяцам/годам): границы группировки (`startDate`/`endDate`, подписи «<10.01.1978»)
  не меняются — Excel требует их согласованности с группами. Это крайние даты без привязки к людям; проверка покажет их
  в отчёте, а «Обновить» сводную в Excel пересчитает их от фейков.
- Производные значения через определённые имена и ссылки на целую строку (`2:2`) не отслеживаются.
- Вне правил заменяются только значения, совпадающие с обработанными целиком (или найденные внутри текста):
  ИНН в колонке без правила записанный иначе, чем под правилом («77 07 083893» против числа), сам не узнается —
  его покажет проверка.
- Книга с датами «1904»: дата числом и та же дата текстом в другом файле могут получить разный сдвиг.
- Имена листов не переименовываются (ссылки на лист остаются целыми): лист, названный по контрагенту,
  проверка покажет в отчёте — переименуйте его в Excel до обработки.
- Повторный прогон по уже обезличенному файлу с ключом не трогает фейки с ID; фейки без ID
  (например, «Фамилия» без ID) обезличатся ещё раз.
- Телефоны короче 10 цифр и номера короче 9 цифр внутри текста не ищутся — слишком легко совпасть случайно.
