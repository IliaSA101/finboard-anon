# finboard-anon — обезличивание Excel-дашбордов

Заменяет реальные персональные данные в `.xlsx` на правдоподобные фейки с ID,
сохраняя дашборд рабочим: формулы, сводные таблицы, диаграммы и оформление остаются как были.

```
Иванов Иван Иванович      →  Калашников Анатолий Алексеевич (ID 1)
Сидоров П.А.              →  Потапов С.В. (ID 2)          ← тот же человек, что и
Сидоров Пётр Алексеевич   →  Потапов Святослав Владимирович (ID 2)
+7 (916) 123-45-67        →  +7 (900) 000-00-01           ← ID в последних цифрах
79161234567 (число)       →  79000000001                  ← тот же номер — тот же ID
client1@mail.ru           →  aleksey.lebedev.1@example.com
7707083893 (ИНН, число)   →  9900000018 (число)           ← контрольная цифра верная, инспекции «00» не бывает
ООО «Ромашка» / Ромашка   →  ООО «Вектор» (ID 3) / Вектор (ID 3)   ← одна организация в любом написании
```

Несколько файлов одного заказчика обрабатываются с **общими фейками**: один человек, одна организация,
один ИНН, телефон, email, дата — один фейк во всех файлах. Поэтому любые связки между колонками и файлами
(организация ↔ ИНН, ФИО ↔ телефон ↔ email ↔ СНИЛС, договор ↔ контрагент, код клиента ↔ ИНН) сохраняются:
каждое значение заменяется само по себе и всегда одинаково, и пары остаются парами.

**Для кого:** для тех, кому нужно передать Excel-дашборд с персональными данными клиентов
(разработчику, аналитику, подрядчику) так, чтобы он остался рабочим, а реальных данных в нём не было.
Программа работает на компьютере пользователя без интернета и ничего никуда не отправляет.

**Статус:** ранняя версия для тестирования на реальных файлах. Перед передачей результата
просмотрите отчёт проверки — он показывает, что могло остаться незаменённым.

## Сборка из исходников

Нужен [Rust](https://rustup.rs/) (проверено на тулчейне `stable-x86_64-pc-windows-gnu`):

```bash
cargo build --release
```

```bash
cargo test
```

Готовые программы — в `target\release\`. Архив для выпуска собирает `tools\release.ps1`
(сборка без путей машины, архив, контрольные суммы).

## Запуск

- **Окно:** `target\release\finboard-anon.exe` (можно перетащить в окно один или несколько .xlsx, или
  `finboard-anon.exe файл1.xlsx файл2.xlsx профиль.json`).
- **Консоль (повторная обработка по готовым профилям):**

```bash
finboard-anon-cli --profile профиль.json --in данные.xlsx --out данные_anon.xlsx
```

```bash
finboard-anon-cli --profile договоры.json --in договоры.xlsx --out договоры_anon.xlsx --profile платежи.json --in платежи.xlsx --out платежи_anon.xlsx
```

  Второй вариант — пакет: несколько файлов за один вызов, у каждого свой профиль, фейки и ключ общие.
  Ключ по умолчанию — общий ключ папки первого файла; если он уже есть, он подхватывается и дополняется
  (`--load-key` / `--key` — указать другой, `--no-key` — не писать).

Тесты и ручная проверка окна — в [TESTING.md](TESTING.md): `cargo test` и мутационная проверка `python tools/mutate.py`.

## Как пользоваться окном

1. **Открыть Excel…** (можно выбрать сразу несколько файлов) или **Добавить файл…** — слева список файлов
   и листы текущего файла, в центре содержимое листа. У каждого файла свои правила.
2. **Автоподбор** ищет заголовки «ФИО», «Исполнитель», «Телефон», «ИНН» и т.п. в строке заголовков таблицы
   и берёт строки под ними до пустой строки, строки «Итого» или следующего заголовка
   (на листе может быть несколько таблиц). Названия разделов вроде «Итоги по исполнителям» не считаются заголовками.
3. Поправить/добавить правило (лист + колонка + диапазон строк + тип):
   - протянуть мышью по ячейкам, или щелчок — начало, **Shift+щелчок** — конец;
   - колонка целиком: щелчок по букве или **двойной щелчок** по заголовку — всё под шапкой до конца листа,
     двойной щелчок по ячейке — от неё до конца; выделение до последней строки даёт правило «до конца»;
   - клавиатура как в Excel: стрелки, Shift+стрелка вверх/вниз, Ctrl+стрелка (к краю данных), PageUp/PageDown,
     Home, Ctrl+Home/End;
   - или ввести диапазон: `C5:C120`, `C5:C` (до конца листа), `B5:D100` (несколько колонок);
   - **Добавить правило**: пересекающееся правило той же колонки заменяется новым (так диапазон сужают);
   - или **Взять выделение** у правила справа.
   Номера строк и буквы колонок закреплены; подсказка у ячейки показывает адрес и правило.
4. Справа у каждого правила — число ячеек и предпросмотр «реальное → фейк» (считается в фоне — на больших
   файлах несколько секунд). Если ниже конца правила в колонке ещё есть данные — предупреждение (и в отчёте).
5. **Обезличить и сохранить…** (один файл) или **Обезличить все файлы…** (несколько — спросит папку для
   результатов) — результаты `<имя>_anon.xlsx`; рядом с исходниками — профили `<имя>_профиль.json`, в папке
   первого файла — общий ключ `КЛЮЧ_ОБЕЗЛИЧИВАНИЯ_НЕ_ПЕРЕДАВАТЬ.csv`.
   При следующем открытии файлов из этой папки профиль и ключ подхватываются автоматически — даже если
   обрабатывать файлы по одному в разные дни, фейки будут те же.

Заголовки («Исполнитель», «ФИО»…) и «Итого» не заменяются, даже если попали в диапазон.
Приписка «(ID n)» от прошлого обезличивания отбрасывается, пометки в скобках вроде «(стажёр)» сохраняются.

Проверить автоподбор без окна: `finboard-anon-cli --detect файл.xlsx`.

## Типы замены

| Тип | Пример результата | ID |
|---|---|---|
| ФИО | `Петров Олег Сергеевич (ID 12)`; пол, порядок слов, инициалы и регистр сохраняются | да |
| Фамилия / Имя / Отчество | те же фейки, что и в полных ФИО (Иванова → Петрова) | по желанию |
| Email | `oleg.petrov.12@example.com` (несколько адресов в ячейке — каждый отдельно) | в адресе |
| Телефон | `+7 (900) 000-00-12`, формат исходника | в номере |
| ИНН / СНИЛС | ID внутри, контрольные цифры корректны | в номере |
| Паспорт | `99 00 000012` | в номере |
| Адрес | `г. Казань, ул. Садовая, д. 5, кв. 7 (ID 12)` | да |
| Организация | `ООО «Вектор» (ID 12)`; форма и кавычки как в исходнике; ИП — с тем же фейковым ФИО, что и в колонке ФИО | да |
| Номер (счёт/карта/договор) | цифры → ID, формат сохраняется; число остаётся числом. Короткий код (до 4 цифр): `Дог1` → `Дог900017` — никогда не совпадает с настоящим | в номере |
| Дата рождения | сдвиг ±180 дней, одинаковый для одной даты в любом виде (число Excel, «15.07.1980», «1980-07-15») | — |
| Маска | каждая буква и цифра → случайная того же вида и регистра, знаки как есть: `АБ-123` → `КМ-570` | — |
| Шаблон: подпись + номер | `Налог 1`, `Должность 2`; подпись берётся из заголовка колонки, у каждой подписи своя нумерация | да |
| Очистить | пусто | — |
| Не менять (защитить) | ячейки остаются как есть, даже если те же значения заменяются в других местах | — |

**Шаблон.** Подпись подставляется из заголовка над диапазоном («Налог» → `НДФЛ` = `Налог 1`, `НДС` = `Налог 2`).
Если шапка попала в выделение, она не заменяется и становится подписью. Подпись можно поправить в правиле.

**Вне разметки** (настройка внизу окна) — что делать с теми же значениями в ячейках без правил:
«заменять везде» (по умолчанию: целые ячейки, внутри текста и формул), «только целые ячейки» или «не трогать»
(формулы без правил тоже не меняются — `СЧЁТЕСЛИ` по реальному ФИО после пересчёта даст 0).
Отдельные области можно защитить правилом «Не менять (защитить)». Сводные, диаграммы и примечания меняются всегда —
иначе в них останутся реальные данные. Оставленное по настройке проверка тоже покажет — отчёт об этом предупредит.

## Прослеживаемость

- Одинаковое значение везде получает **один фейк и один ID** — на всех листах, в сводных, диаграммах, формулах.
- Одно значение узнаётся в любом написании, и фейк у него один:
  - телефон — по номеру: `+7 (916) 123-45-67`, `8 916 123 45 67`, число `79161234567`;
  - ИНН, СНИЛС, паспорт, счёт — по цифрам: `7707083893` числом, `77 07 083893`, `ИНН: 7707083893`;
    один номер под типами «ИНН», «СНИЛС», «Паспорт», «Номер» получает одни и те же фейковые цифры;
  - организация — по названию без формы и кавычек: `ООО «Ромашка»`, `ООО "Ромашка"`, `Ромашка`, `Ромашка, ООО`,
    `Общество с ограниченной ответственностью «Ромашка»`; внутри текста («Оплата ООО «Ромашка»») — тоже,
    и всегда с тем же ID, что в колонке: `Оплата ООО «Вектор» (ID 12)` (ID — после закрывающей кавычки);
  - email и адрес — без учёта регистра и лишних пробелов; дата — по дню.
- «Иванов И.И.» связывается с «Иванов Иван Иванович», если такой человек в данных один, — в том числе в другом файле.
- Значение, размеченное правилом в одном файле, заменяется и в других файлах — даже в колонке без правила
  (ИНН контрагента в выгрузке платежей).
- Если одни и те же значения в разных файлах размечены **разными типами** (в одном «ИНН», в другом «Текст»),
  фейки у них разные и связка рвётся — в журнале будет предупреждение, где поправить тип (без самих значений).
- **Ключ** (`КЛЮЧ_ОБЕЗЛИЧИВАНИЯ_НЕ_ПЕРЕДАВАТЬ.csv`: Тип; ID; Реальное значение; Фейковое значение) — один на папку.
  Открывается в Excel и позволяет по ID найти реального человека. Ключ содержит персональные данные — храните у себя.
  С ключом те же люди и организации получают те же ID и фейки в любом файле и при любом запуске.
  Ключ прежних версий (`<имя>_КЛЮЧ_НЕ_ПЕРЕДАВАТЬ.csv`) тоже подхватывается, а новые записи идут в общий.
- Прогон без ключа («Не использовать») не затирает общий ключ: прежний сохраняется как `…_прежний.csv`.
- Пакет (все файлы за один прогон) надёжнее, чем по очереди: фейк заранее не совпадёт ни с одним реальным
  значением ни одного файла пакета, а сокращения «Иванов И.И.» связываются с полными ФИО из всех файлов.
  По очереди фейк учитывает только уже обработанные файлы.

## Можно ли восстановить реальные данные

По одному обезличенному файлу — нет: фейк выбирается по хэшу «соль + значение», ID — порядковый номер.
Соль случайная на каждый запуск и нигде не сохраняется, поэтому подобрать фейки для подозреваемых людей
нельзя, а профиль (`.json`, только правила и настройки) можно пересылать.
Обратно — только по ключу; он же сохраняет те же фейки и ID между запусками. Оговорки:

- Намеренно сохраняются пол, формат («Фамилия И.О.»), код страны телефона, первые 4 цифры номеров
  от 12 цифр, примерный год рождения (сдвиг ±180 дней).
- Колонки без правил (суммы, города, даты сделок) не меняются — по их сочетанию клиента иногда можно узнать.
  Это псевдонимизация: для передачи разработчикам обычно достаточно, для публикации — нет.

## Что именно меняется в файле

Программа правит XML внутри xlsx, не пересохраняя книгу через Excel:

- ячейки в диапазонах правил (формулы не трогаются — они пересчитаются от фейков);
- общие строки, кэши результатов формул, строки внутри формул (`СУММЕСЛИ(…;"Иванов И.И.";…)`);
- кэш сводных таблиц (по строкам и колонкам источника), кэши диаграмм, примечания, надписи;
- ФИО/email/телефоны/организации внутри длинного текста («Ответственный: Иванов Иван Иванович»,
  «Оплата ООО "Ромашка"») — по границам слов;
- длинные числа (ИНН, телефон, счёт) в колонках без правил, если такое же значение обработано здесь, в другом
  файле пакета или есть в ключе;
- автор и компания в свойствах файла, авторы примечаний;
- служебные поля, где Excel хранит пользователя: имя в защите от записи и в журнале общей книги, кто обновлял
  сводную, папка, где сохранялась книга; имя пользователя в путях `C:\Users\<имя>\…` (гиперссылки, внешние книги,
  подключения, база гиперссылок) заменяется на `user`. Пути в тексте ячеек меняют только правила;
- `fullCalcOnLoad` — Excel пересчитает формулы при открытии.

- формулы под правилами (например, ФИО из другой книги): формула остаётся, кэш результата заменяется фейком,
  кэш внешней ссылки — тоже;
- формулы, результат которых зависит от ячеек с ПДн (`ЛЕВСИМВ(ФИО)`, `ТЕКСТ(дата)`, `=C2`): если результат
  совпадает с обработанным значением — заменяется, иначе кэш **очищается**. Excel пересчитает при открытии;
  программы, читающие файл без пересчёта (pandas, openpyxl), увидят в таких ячейках пусто. Числовые итоги
  (СУММЕСЛИ, СЧЁТЕСЛИ) не очищаются;
- даты в книгах «1904», текст, разрезанный на фрагменты форматирования, шапки умных таблиц и ссылки на их
  колонки, адреса в гиперссылках `mailto:`.

Всё остальное копируется байт-в-байт.

После записи результат **проверяется**: если реальные значения из правил где-то остались
(например, в ячейке вне правил), в журнале будет указано, где именно.

## Ограничения

- Только `.xlsx` / `.xlsm` (`.xls` пересохраните в Excel). Файл не должен быть защищён паролем.
- Большие листы читаются и пишутся потоком: 500 000 строк × 100 колонок (400 МБ) — около 2 минут, меньше 100 МБ
  памяти. В окне показываются первые 20 000 строк листа.
- Значения, которые не попали в правила и не совпадают с обработанными, не меняются — смотрите отчёт проверки.
- Сводная с группировкой дат (по месяцам/годам): границы группировки (`startDate`/`endDate`, подписи «<10.01.1978»)
  не меняются — Excel требует их согласованности с группами. Это крайние даты без привязки к людям; проверка покажет их
  в отчёте, а «Обновить» сводную в Excel пересчитает их от фейков.
- Производные значения через определённые имена и ссылки на целую строку (`2:2`) не отслеживаются.
- Вне правил заменяются только значения, совпадающие с обработанными целиком (или найденные внутри текста):
  ИНН в колонке без правила записанный иначе, чем под правилом («77 07 083893» против числа), сам не узнается —
  его покажет проверка.
- Книга с датами «1904»: дата числом и та же дата текстом в другом файле могут получить разный сдвиг.
- Имена листов не переименовываются (ссылки на лист остаются целыми): лист, названный по контрагенту,
  проверка покажет в отчёте — переименуйте его в Excel до обработки.
- Повторный прогон по уже обезличенному файлу с ключом не трогает фейки с ID; фейки без ID
  (например, «Фамилия» без ID) обезличатся ещё раз.
- Телефоны короче 10 цифр и номера короче 9 цифр внутри текста не ищутся — слишком легко совпасть случайно.

## Пример

`samples/demo_dashboard.xlsx` — синтетический дашборд (данные с 5-й строки, итоги внизу,

`samples/demo_dashboard_anon.xlsx` — результат.
